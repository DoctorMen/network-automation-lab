# This lab against OROS 0.3

Every requirement in [the standard](standard.md), scored against this repository and its running lab on 2026-10-15, and the rows wave 2 changed on 2026-10-16.

**27 pass, 16 partial, 18 fail.** The first scoring gave 0 pass, 13 partial and 48 fail. The BFD, collection, locate, firewall-control and records work brought that to 6 pass, 10 partial and 45 fail, and the canary rollout, edge filtering, backups, runbooks and secrets work to 15 pass, 14 partial and 32 fail. Wave 2's monitoring and logging work (the NOC's state checks and central logs, alert quality, loss and evidence, log volume and the detection table, and named accounts with command records) brought it here.

How each requirement is scored:

- **pass**: the requirement's *Pass* test is demonstrated in this lab by a test or lint in this repo, and that test fails when the requirement isn't met. Each one was checked by breaking what it guards (removing the config line, truncating the backup, injecting the fault) and watching the test go red.
- **partial**: real pieces of the requirement are in place, and the row names them, but the *Pass* test is not demonstrated. The row says what is missing. The before figures used the same rule.
- **fail**: nothing here demonstrates the *Pass* test.

Each first score was then checked again, independently, against the code and the live lab, and several were marked down on that check. Both passes were AI-assisted, like the coding behind the standard ([how OROS was made](README.md)). The lab is 24 containers (8 network nodes and the NOC's 16 sidecars), so a pass shows the method works at lab scale, not that a production network meets the requirement. `make test` checks that this page lists all 61 requirements, that the totals add up, and that every test it names exists.
