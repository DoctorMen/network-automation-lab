## Context

NOT-1's example is a BGP session shut while the peer still pings. The routers run FRR 8.4.1 with no SNMP; their state is in FRR's JSON show output.

## Decision

frr_exporter v1.3.1, with its default collectors (bgp, ospf, bfd), reads each daemon over its vty socket. The router's /var/run/frr is a bind mount shared with the sidecar; the router empties it and gives it to the frr user before FRR starts, so a stale pid file from an earlier run can't point FRR's start script at another process (decision 0018).

## Consequences

The vty socket is the same one vtysh uses, so the exporter could send configuration commands as well as read; the mount's :ro does not stop a socket write (accepted as RISK-32 in docs/risks.yml). It is a one-maintainer project: the image is pinned by digest, and the fallback is the same JSON read by our own code. Route-table state is not exported (frr_exporter v1.3.1 has no route collector), a gap listed in monitoring/coverage.yml.
